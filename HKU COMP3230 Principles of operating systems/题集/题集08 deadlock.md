## 课件证明

### P1. 死锁四必要条件的必要性

- **陈述**: 死锁发生当且仅当互斥 / 持有并等待 / 不可抢占 / 循环等待四条件同时成立。
- **证明 (思路)**:
  - 必要性: 死锁时全体阻塞, 每个线程持有资源等他人资源 → 持有并等待成立; 环中 T1 等 T2 等 ... 等 T1 → 循环等待成立; 资源被持有不能被夺 → 不可抢占成立; 资源独占 → 互斥成立。
  - 充分性: 四条件成立 → 存在循环等待, 环中每个线程持有他人所需且不可抢占 → 无人能继续 → 死锁。
- **来源**: 讲义 §4

### P2. 资源分配图有环 → 循环等待

- **陈述**: 资源分配图中存在环 ⟺ 循环等待条件成立 (单类资源时)。
- **证明**: 环 T1→R4→T2→R3→T1 表示 T1 持 R4 等 R3, T2 持 R3 等 R4, 即环中每个线程等下一个线程持有的资源 → 循环等待定义。
- **来源**: 讲义 §4.1, §7.1

### P3. 全序资源申请破坏循环等待

- **陈述**: 给所有资源类型编号, 要求线程按递增顺序申请, 则不会循环等待。
- **证明 (反证)**: 若存在循环等待 T1 等 R_a 等 T2 等 R_b 等 ... 等 T1, 则按申请顺序 a < b < ... < a, 矛盾。故无环。
- **缺点**: 资源利用率低 (须先持小号才能拿大号)。
- **来源**: 讲义 §5.1

### P4. 银行家算法: 安全状态判定

- **陈述**: 仅当试分配后状态安全才授予请求。
- **证明 (安全性算法)**:
  1. 试分配: `available -= req`, 该线程 `loan += req`, `claim -= req`
  2. 找 `claim ≤ available` 的线程, 假设它完成并归还 `loan` → `available += loan`, 标记完成
  3. 重复直到所有线程完成 → 安全; 若中途找不到 → 不安全
- **例** (课件 p.18): total=12, available=2; T1 max=4 loan=1 claim=3; T2 max=6 loan=4 claim=2; T3 max=8 loan=5 claim=3。
  - T2 请求 1: 试分配后 available=1, T2 claim=1 loan=5。T2 claim=1≤1 → 完成, available=6; T1 claim=3≤6 → 完成, available=8; T3 claim=3≤8 → 完成。**安全**, 授予。
  - T1 请求 1: 试分配后 available=1, T1 claim=2 loan=2。T1 claim=2>1, T2 claim=2>1, T3 claim=3>1 → 无可完成者。**不安全**, 不授予。
- **来源**: 讲义 §6.2; 2023 Final Q6

### P5. 一次性申请全部资源破坏持有并等待

- **陈述**: 线程开始时一次性申请全部所需资源, 要么全拿到要么不拿, 则不会持有并等待。
- **证明**: 线程要么不持任何资源 (申请失败), 要么持全部所需资源 (不再等额外资源) → 持有并等待条件不成立。
- **缺点**: 资源利用率低; 可能饥饿 (大请求者等很久)。
- **来源**: 讲义 §5.2

## 练习题

### 1. 哲学家就餐: 朴素解的死锁

- **题目**: 五人同时拿左叉再等右叉, 会怎样?
- **思路**: 每人持左叉等右叉 → 循环等待 (五人成环) → 死锁。预防: 给叉编号, 每人先拿小编号叉。
- **来源**: 讲义 §3

### 2. 银行家算法: 多类资源 (2023 Final Q6 风格)

- **题目**: 给 Max/Allocation/Need/Available 表, 判断请求是否安全; 新进程独立于上一问。
- **思路**: 试分配 → 安全性检查 (找可完成序列); 注意新进程要重新算 available 与各 claim。
- **来源**: 2023 Final Q6; 讲义 §6.2

### 3. 检测与恢复: 何时用

- **题目**: 为何实际 OS 多用检测与恢复而非预防/避免?
- **思路**: 预防代价高 (利用率低), 避免需全局知识 (假设太强); 检测多数时候开销小, 死锁偶发时才恢复。
- **来源**: 讲义 §7, §8

### 4. 破坏不可抢占的代价

- **题目**: 银行转账 (John 减 100 + Mary 加 100) 中途释放资源的后果?
- **思路**: 已做的减法要回滚 (undo), 否则半成功不允许; 重启时从头或从 checkpoint 恢复, 开销大。
- **来源**: 讲义 §5.4

### 5. 死锁 vs 饥饿

- **题目**: 哲学家解法中, 无死锁但某哲学家总拿不到叉, 是死锁吗?
- **思路**: 不是死锁 (无循环等待全体阻塞), 是饥饿 (个别线程无限期推迟)。预防要兼顾两者。
- **来源**: 讲义 §3, §8
